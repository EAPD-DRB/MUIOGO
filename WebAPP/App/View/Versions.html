MUIO ver.5.7.0, 20261005

  1. Code Commodity balance level: each commodity can be balanced per timeslice, per season or once a year. Cases from earlier versions keep every commodity at timeslice level, as before.
  2. Code New Operational Profile parameter, and annual Production/Use by Technology by Mode results (the timeslice versions are now named "- Ts").
  3. Code Solver model updated to MUIO 5.7 (the release's model without the performance rewrite meant for 5.8, which did not solve large models reliably). Each commodity keeps a single yearly balance row, so its shadow price is not split between duplicates.
  4. Func New "Shadow price - Timeslice energy balance" result.
  5. Func New "Shadow price - Commodity (annual)" result: one yearly marginal price per commodity, combining its timeslice (or season) prices with its yearly balance price, so it stays meaningful whatever balance level the commodity uses.

MUIO ver.5.6.0, 20260601

  1. Func Indicator framework — users can now define custom indicators per case (e.g., production intensity by technology) that flow through to the result viewer.
  2. Func Dual variables (shadow prices for emission limits, energy balance, and user-defined constraints) now live in a dedicated Duals.json data file and persist through the Save flow.
  3. Tech Solver discovery extended with macOS Homebrew and Linux distro paths as a fourth fallback tier. The solver subprocess now only sets cwd to the solver folder when running a bundled binary, so system installs no longer run from /usr/bin.
  4. Code Data-driven schema: Variables.json, Duals.json, Indicators.json, and Parameters.json now carry setrelation and name per entry, matching MUIO 5.6. Legacy Config.VARIABLES_C/Config.DUALS Python dicts removed.
  5. Code Backend cleanup: removed roughly 1,500 lines of dormant backup methods from DataFileClass; OsemosysClass refactored to use the shared HelpersClass for parameter, variable, and indicator building.

MUIO ver.5.5.0, 20260331

  1. Func Added DataFile diagnostics for viewing the current model file and runtime log from the UI.
  2. Func Added a standalone ModelFile page with MathJax-based equation rendering and readable fallback when MathJax is unavailable.
  3. Func Scenario-order dialog now includes toggle-all selection without changing the locked base scenario behavior.
  4. Code Cleanup and case-run bookkeeping were aligned with upstream v5.5 so saved view definitions are preserved and result metadata stays consistent.
  5. Code Updated the solver model and synchronized frontend result metadata with upstream v5.5 definitions.
  6. Tech Runtime logging now uses a backend-managed log path outside the static web tree, with read-only UI access through backend routes.
